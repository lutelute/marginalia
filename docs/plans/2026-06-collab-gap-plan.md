# 共同編集・履歴共有のギャップ解消計画

**作成日**: 2026-06-10（v1.7.0 リリース時点）
**目的**: 「md を正として編集履歴を共有し、そのまま論文になる」構想と現状のギャップを段階的に埋める。
**前提**: v1.7.0 で author 連動・外部変更時の `.mrgl` 再読込・再アンカー常時化は実装済み。

---

## ギャップ一覧（v1.7.0 時点の残課題）

| # | ギャップ | 影響する運用 | 規模感 |
|---|---------|------------|--------|
| G1 | `.mrgl` 単独の外部変更を検出しない（監視対象は `.md` のみ） | git pull で注釈だけ更新された場合に気づけない | 小 |
| G2 | author が表示名ベース（ID なし）。同名衝突・改名追跡が不可 | 3人以上での共同校閲 | 中 |
| G3 | 注釈履歴が操作ログ止まり（最大100件・サマリ文字列のみ） | 「いつ誰が何を変えたか」の共有 | 中 |
| G4 | 差分ビューがバックアップ比較専用。注釈と差分の対応表示がない | 校閲ラウンド間のレビュー | 中〜大 |
| G5 | 論文ワークフローの実戦検証不足（paper テンプレートでの通しビルド） | md → 論文 PDF | 小（検証）〜中（改善） |
| G6 | コンフリクト時の `.mrgl` マージ支援なし（JSON の git コンフリクトは手解決） | 同一ファイルへの同時注釈 | 大 |

---

## フェーズ計画

### Phase A: 共有の信頼性を固める（推奨着手順: 最初）

**A-1. `.mrgl` の外部変更検出（G1）**
- `fileWatcher.js` の監視対象に、開いている md に対応する `.mrgl` パスを追加（watcher を2本持つか、`fs.watch` をディレクトリ単位にして対象2ファイルをフィルタ）
- `.mrgl` 変更イベント時: 未保存の注釈編集がなければ**サイレント再読込**（バナー不要、注釈は本文と違い編集中状態が短いため）。注釈フォーム入力中なら現行バナーと同様の通知に倒す
- 自己保存ガード: `AnnotationContext.saveMarginalia` の直後イベントを無視（FileContext の `lastSaveAtRef` と同じパターン）
- 検証: CDP E2E（v1.7.0 で確立した手法）で `.mrgl` のみ外部更新 → UI 反映を確認

**A-2. author の ID 化（G2）**
- スキーマ: `AnnotationV2.author: string` は維持（後方互換）し、`authorId?: string` を追加。`_version` は `2.1.0` に上げ、読み込みは 2.0.0 をそのまま受理（追加フィールドのみなのでマイグレーション不要）
- `SettingsContext` の `User.id`（既存）を `authorId` に記録。表示は従来どおり `author`（名前）
- 表示側: `users` に一致する `authorId` があれば色バッジを表示（既存の `User.color` を活用）。未知 ID はニュートラル色
- 共有時の前提を README に明記: 各編集者が設定→ユーザータブで自分の名前を設定する

### Phase B: 履歴の共有価値を上げる（G3, G4）

**B-1. 履歴エントリの構造化（G3）**
- `HistoryEntryV2` に `author`/`authorId`/`detail`（変更前後の content 等の構造化データ）を追加
- 上限 100 件 → ファイルサイズ上限ベース（例: 500KB 超で古い順に間引き）に変更
- 注釈の status 遷移（resolved/orphaned/reassign）も履歴に記録（現状は追加時のみ）

**B-2. 校閲ラウンド差分ビュー（G4）**
- 既存の `DiffPanel`/`DiffViewer`（unified/side-by-side 実装済み）を流用し、「md バックアップ vs 現在」に**注釈マーカーをオーバーレイ**する
- データは揃っている: バックアップ md + 現在 md + 注釈セレクタ（TextPosition）
- スコープを限定: 差分行に重なる注釈をガターに表示するだけでも校閲レビューには十分

### Phase C: 論文ワークフロー実戦投入（G5）

**C-1. paper テンプレート通し検証（実装より検証が先）**
- 実際の執筆中文書（または `report-build-system/src/examples/paper-sample.md`）で `build_document`（marginalia-build MCP）→ PDF を通し、つまずきを洗い出す
- チェック観点: 日本語/英語混在、数式ディレクティブ、引用（check_citations）、図表相互参照、XeLaTeX フォント
- 出てきた問題を Issue 化して個別対応（テンプレート修正 or ディレクティブ拡張）

**C-2. 注釈→校閲レポート出力**
- `.mrgl` から「校閲コメント一覧」md/PDF を生成（type/status/author 別）。共同執筆者への申し送りに使う
- annotation-core に pure 関数として実装すればテスト容易・Web 版でも動く

### Phase D: 同時編集の本格対応（G6 — 必要になってから）

- `.mrgl` の git merge driver（annotations 配列を id ベースで union マージする小スクリプト）を `scripts/` に追加し、`.gitattributes` で指定
- リアルタイム共同編集（CRDT）は現時点で**やらない**（運用は「pull → 編集 → push」の非同期共有で足りる想定。需要が出たら再評価）

---

## 推奨順序と理由

```
A-1 (.mrgl 監視) → A-2 (authorId) → C-1 (論文通し検証) → B-2 (差分×注釈) → B-1 (履歴構造化) → C-2 → D
```

- A は v1.7.0 の直接の続きで小さく、共有運用の信頼性が一段上がる
- C-1 は実装ではなく検証なので早めに回すと B 以降の優先度判断材料になる
- D はコストが大きく、まず A+B の運用で困るかを見てから

## 各フェーズ共通のゲート

`tsc --noEmit` 0 / `vitest` 全パス / `eslint` 0 error（warning はベースライン 67 以下を維持）/ `npm run build` 成功 / 挙動変更は CDP E2E で実機確認 → コミット & push
